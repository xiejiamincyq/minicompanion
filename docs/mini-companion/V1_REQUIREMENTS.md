# Mini Companion V1 要求与冻结状态

来源：项目所有者2026-09-19任务书。产品范围已明确；电路料号/电源/NFC/机械尚未冻结。不得用本文替代最终硬件规格。

## 已确定范围

- 保留 ESP32-S3-MINI-1-N4R2、HS20HS072RX、USB-C充电/原生USB烧录、三操作键、背光、电池，尽量复用45×50mm现有四层板与60mm级外壳。
- 三操作键为LEFT/OK/RIGHT；实际左右位置必须结合装配方向核实，不能仅照旧网络名。独立POWER不能以复位或唤醒键代替。
- 删除状态LED、电机及专属驱动。不得新增RGB、蜂鸣器、光敏、音频、摄像头、触屏、额外传感器。
- NFC实现两台相同设备靠近后双方识别、自有ID和互动。无网络账号、云服务；Wi-Fi不初始化，BLE不作为V1依赖；不做卡片克隆/凭证绕过。
- 保留MIT许可和原作者版权。只在mini-companion-v1分支开发；每阶段小提交，不push、不创建PR、不下单。
- 硬件修改优先KiCad MCP，次选官方CLI/API；本会话未发现可调用MCP。禁止将文本修改成功当验证。

## 交付与验收

1. 最终原理图/PCB有可解释的ERC/DRC报告、真实电气错误清零、明确警告处置、极性/封装/Pin1/天线keepout与3D复核。
2. 新制造包从冻结版本重导Gerber/Drill/BOM/CPL至hardware/jlcpcb/mini_companion_v1；禁止旧包改名冒充。未放行前不得生成“可下单”声明。
3. 采购表区分贴片/单购，显示、电池、NFC和机械件具备明确规格。实际库存/报价在采购前刷新。
4. 实物验证分阶段：限流供电裸板→USB/MCU/屏/键→电源和保护→两设备NFC→整机壳内验证。CAD检查不能证明续航、RF距离、温升和电池安全。
5. 硬件冻结后生成SOFTWARE_REQUIREMENTS.md和SOFTWARE_AGENT_PROMPT.md。包含最终全部GPIO/电平/时序、电源行为、存储与防重复相遇记录、异常恢复、离线UI、低电处理和测试。当前不写固件。

重大尺寸变化、电芯化学体系变化、安全路线选择、严重上游缺陷、NFC目标不满足、昂贵采购及实际下单均遵从用户任务书的暂停点。
