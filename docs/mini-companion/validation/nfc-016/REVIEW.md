## 已画入的接口

- U2为TMUX1511PWR，按14脚PW版本生成符号并指定标准TSSOP-14封装；VDD接VLOGIC_SWITCHED，C3为100nF去耦。
- 通道1传SDA，通道2传SCL；两个SEL共用NFC_BUS_CONNECT，并由R5 100k下拉。未用通道的控制和信号接地。它是双向模拟通路，不是电平转换器或电气隔离器。
- R6、R7各4.7k上拉至主板切换电源；U216自带的2.2k上拉仍在模块侧，没有在本图重复添加。
- J4为主板评审接口：1 HOST_SDA、2 HOST_SCL、3 NFC_BUS_CONNECT、4 GND。GPIO尚未分配。
- J5为拟接U216的接口：1 SCL、2 SDA、3 NFC_5V、4 GND，依据nfc-014保存的原厂图。物理连接器、插头方向和线束未定型；不可据线色下单。J1–J4均为评审边界占位。

连接参考：[TMUX1511 Rev.B](https://www.ti.com/lit/ds/symlink/tmux1511.pdf)第4、5、7节。器件在VDD=0、信号不超过3.6V的规定条件下有掉电保护；全温规定条件的IPOFF为±2µA，不能采用25℃低电压条件的±10nA作为全范围保证。电源有效且SEL低时断开，内部下拉不替代本图外部下拉。常供电静态电流还须加入整机预算，不能忽略。

## 电源状态边界

| 状态 | 控制要求 | 本候选能说明什么 |
|---|---|---|
| 主板开、NFC关 | BUS_CONNECT=0，NFC_ENABLE=0 | 在开关有效供电、控制低电平条件下断开主机上拉与模块信号 |
| NFC启动 | 保持BUS_CONNECT=0，再启用NFC电源 | 不能仅凭使能高就断言模块供电已稳定；有效等待/检测条件未定 |
| 两侧正常、通信 | 电平和电源均合格后BUS_CONNECT=1 | 接通SDA/SCL；仍须验证时序、电平及总线电容 |
| 正常关闭NFC | 先结束事务，BUS_CONNECT=0，确认断开后NFC_ENABLE=0 | 给出了所需硬件接口时序，没有实现固件或保证具体延时 |
| 主板VDD已为0、模块有残余电压 | 控制默认低，信号须满足手册范围 | 可引用器件规定的掉电隔离；不是零漏电保证 |
| 电源处于中间电压，或模块意外失电但BUS_CONNECT仍为1 | 尚无自动电源有效联锁 | **未解决**；可能通过上拉反灌。不能把静态检查冒充任意掉电安全 |

上述控制是NFC接口要求，不改变电芯NTC或充电保护必须由硬件独立承担的决定。用户提出的触发方式选择仍未明确，不在本轮擅自冻结。

## 电平和上拉估算

按[TI SLVA689](https://www.ti.com/lit/an/slva689/slva689.pdf)的RC近似，4.7k与2.2k并联名义约1.499k，假设总电容100pF时上升时间约127ns。假设模块3.3V、两边上拉均1%、主板静态高端3.222584V，拉到零电压的总电流约2.21mA，按4.5Ω估算开关压降约9.93mV。模块供电容差、上拉实际公差、输入阈值及实测电容未闭环，这些只是条件计算，不能据此宣布400kHz可靠。

两个域接通后上拉相互影响；该开关不限制高电平到MCU电源。上电/掉电中间阶段须另外审核。初始验证可从100kHz开始，最终速率以实际边沿和模块响应为准，本轮不编写软件。
