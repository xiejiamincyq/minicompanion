# 可直接交给软件代理的任务

请为Mini Companion V1完成硬件冻结前的电脑交互原型与独立业务逻辑。本任务可以直接执行，无需购买硬件。先制作可操作的灰盒原型，不提前制作完整美术或扩展产品功能。

产品是可随身携带、可赠送的离线小设备。首批5–10台，材料预算目标50–100元/台；目标至少两天续航，每天约20分钟使用。两台同款设备在指定区域接触时通过NFC互相识别，双方显示互动结果。保留ESP32-S3-MINI-1-N4R2、HS20HS072RX屏、LEFT/OK/RIGHT、独立POWER、单节锂电和USB-C。没有Wi-Fi业务、BLE依赖、云账号、远程服务器、电机、指示LED或声音。

硬件代理正在修改原Devotchi项目。原仓库firmware目前只有README；packages内服务端/客户端属于旧联网通知产品，不能直接当成本任务应用。若提供仓库，请先只读检查；不要为了运行旧项目而引入联网业务。

现在只实现以下范围：

1. 本地电脑可运行的原型，同时显示两个独立设备A/B。用240×320像素矩阵模拟屏幕，方向可配置。每台设备用LEFT/OK/RIGHT三个事件导航，子页面有明确返回入口。键盘模拟三键；断电、电池、接触/移开、重复报文及断链等测试控件放在设备屏幕外。
2. 页面包含启动、Home、NFC等待/识别/待确认/成功/失败、互动结果、基础设置和设备信息。Home用简单陪伴形象占位图。设置先提供抽象背光和屏幕超时；参数可配置。电池支持正常/低电/充电/未知，不能伪造未经校准的精确剩余电量。
3. 为每台模拟设备持久化稳定ID、按对方ID关联的已确认相遇记录和未完成会话。一次会话使用稳定标识；重复报文、保持接触及重试不增加次数。模拟器移开再接触形成新事件。真实NFC的移开判断/去重时序暂不实现为固定硬件结论。
4. 双方独立运行状态机；可注入丢包、重复、断链、存储失败和任意阶段掉电。断链可能使双方暂时不同步，应显示待确认并在恢复通信后核对补全，不能声称无线通信可以保证两端绝对同时完成。保存失败不能显示可靠保存成功。
5. 时钟接口区分开机单调时间与可信日历。当前没有断电RTC保证，重启失去可信时间后应显示“时间未知”，保留对象与次数，不能推算虚假的“距上次见面3天”。
6. 普通操作中及时可靠保存重要状态，不把保存全部押在机械关机回调上。存储格式带版本，并有明确恢复、容量和保留策略。最终Flash后端与写入磨损策略留给固件阶段。
7. 使用Input、Display、NfcTransport、Storage、Clock、Power、Backlight等接口隔离业务和硬件。真实NFC芯片、总线/GPIO、ADC分压、充电状态引脚、POWER检测能力、背光电气范围、显示方向和待机唤醒尚未冻结，不写死它们。当前按键基线仅供参考：元件层正面、USB朝下时LEFT=GPIO5、OK=GPIO6、RIGHT=GPIO4，按下低电平；最终以硬件交接表为准。
8. 不实现永久一对一绑定、秘密留言、纪念日、关系等级、喂养或复杂养成；识别基础先做到本次双方身份交换及确认。设备ID用于识别和去重，不作为安全认证凭证。

开发组织：在独立目录或工作树实现，禁止修改hardware、case及硬件代理文档，不推送或发布。选择适合快速本地验证的技术栈并解释；如选浏览器原型，明确其不是可直接烧录ESP32的固件。不要在本轮编写真实NFC驱动或充电控制。

验收至少包括：三键遍历全部页面；A/B正常接触各记一次；同会话重复不增加；移开后新接触可以增加；重启恢复；双方不同阶段断电与断链可恢复且无重复；存储失败不显示已保存；未知版本、无效/过长消息和自身ID不造成崩溃；时间未知诚实显示；低电与充电可演示。测试必须验证行为，不只复述实现。

请交付运行README、可操作原型、关键状态机与数据结构说明、自动测试结果、模拟限制及待接入硬件清单。用户无需已有工具或开发板。原型通过不等于实机NFC、续航和充电安全通过。
