# HW-NFC-017：NFC 总线静态欠压联锁候选

日期：2026-09-30。Astra 实施及自审，独立二审未完成。只修改 NFC 独立候选，没有修改主板、电池保护或用户软件。新增 U3、R8–R12、C4，共 7 个器件；未冻结生产 BOM、成本或实物板框。

TASK ID：HW-NFC-017；MODEL：Astra；OBJECTIVE：增加稳态欠压时的总线断开条件；INPUTS：016 候选、TI TPS3780 手册；MUST KEEP：升压电路及主板现状；ALLOWED TO MODIFY：NFC 独立候选、验证记录及任务状态；DO NOT MODIFY：主板、用户软件和其他既有修改；TOOLS：KiCad MCP、CLI、Python、官方资料；VALIDATION：网表合约、ERC、错接注入、阈值枚举、PDF；OUTPUT：候选图和可复现证据；RISK：响应延迟、电平、模块内部供电、成本和独立二审未闭环。

## 电路与接口变化

U3 为 TPS3780ADBVR，A 型 0.5% 滞回、DBV/SOT23-6 封装。按原厂 DBV 引脚表：1 VDD、2 OUT1、3 OUT2、4 SENSE2、5 GND、6 SENSE1。不要用 DRY 封装的引脚编号，也不能换成推挽输出的 TPS3779 后直接并联输出。

两个开漏输出共同接 NFC_BUS_CONNECT。J4.3 改为 HOST_NFC_BUS_REQ，经过 R8 10k 到该节点，保留 R5 100k 下拉及 TMUX1511 两路 SEL。这样 MCU 即使维持高请求，任一欠压输出拉低时，串联电阻也能限制争流；按请求不高于 3.222584V、R8 -1% 计算，上界约 0.3255mA，低于手册 VOL=0.25V 的 0.4mA 测试电流。未选定 GPIO，因此 VOH、SEL VIH 和漏电角落仍需核实。

VDD 接 VLOGIC_SWITCHED，C4 100nF 去耦。SENSE1 用 15.8k/10k 监测主控切换电源，SENSE2 用 29.4k/10k 监测 NFC_5V；四只分压电阻均为 0.1%。原升压和 I²C 通路保持，原有 56 个引脚只有 J4.3 的网络更名。

依据：[TI TPS3780 数据手册](https://www.ti.com/lit/ds/symlink/tps3780.pdf)，第 6、7.5、7.6、8、9 节，2026-09-30 复核。两个输出是开漏；以下结论仅在器件有效供电及响应完成后成立。

| 请求 | 主控监测 | NFC 5V 监测 | 稳态控制 |
|---|---|---|---|
| 低或高阻 | 任意 | 任意 | 默认断开，仍受器件供电规格限制 |
| 高 | 欠压 | 任意 | OUT1 拉低，断开 |
| 高 | 正常 | 欠压 | OUT2 拉低，断开 |
| 高 | 正常 | 正常 | 输出释放，允许请求接通；电平条件须另验 |

滞回区间保留先前状态，不按简单布尔阈值处理。硬件联锁不替代正常关机时先撤销总线请求、后关闭 NFC_ENABLE 的接口要求。

## 阈值预算

使用上下阈值 ±1%、电阻 ±0.1%、输入漏电 ±15nA 枚举独立角落。公式为 Vrail = Vthreshold × (1 + Rtop/Rbottom) + Ileak × Rtop。漏电指标在手册规定的 SENSE=0 或 VDD 测试条件下给出，中间偏置还需要确认，以下是条件计算。

| 电源 | 上升释放范围 | 下降拉低范围 |
|---|---|---|
| 主控 | 3.04575–3.11538V | 3.03044–3.09972V |
| NFC 5V | 4.64993–4.75894V | 4.62656–4.73503V |

上升上界低于已有静态输出下界（主控 3.137544V、NFC 约 4.834V）。这仅说明静态阈值有间隔，不能保证 PFM 纹波、负载阶跃和启动期间不抖动。A 型滞回较小，必须实测。

分压在主控 3.18V、NFC 4.97V 时分别消耗约 123.3µA、126.1µA；NFC 关闭后后者衰减。U3 自耗电另计，整机待机预算不得忽略新增分压及原 TMUX 功耗。未获得完整国内小批量报价，不能据此批准整机超预算。

## 仍未解决的边界

- 下降响应 10µs、启动 570µs 是指定条件下的典型值，没有可引用的最大响应保证。急速跌落、短路和启动过程不能按零延迟保护处理。
- 监测的是模块 5V 输入，没有直接监测模块内部 3.3V LDO。内部故障、上升延迟和模块电平容差仍可能造成反灌或超出主控引脚范围。
- TPS3780 正常工作电源范围从 1.5V 起；POR 区间输出能力取决于手册条件，低于 POR 不确定。TMUX 的 VDD=0 保护也不等于整个棕断区间的保证。
- 约 3.03V 的最低主控断开门限不能单独证明模块高电平低于主控 VDD+0.3V。优先完成这个电平角落审查；如不成立，应改用合适的电平转换/隔离路径，不能靠软件等待掩盖。
- GPIO、连接器、电感/电容实际料号、成本、PCB 布局、两机通信和实物验证尚未完成。触发方式未被用户明确选择。

## 验证证据

KiCad MCP 生成符号、放置和接线；结构化文本只调整 J4.3 名称、标题及可读性，有修改前备份。官方 CLI 导出的格式整理前后网表完全相同。

复现：在仓库根目录用 KiCad CLI 对候选图导出 XML 到本目录 final.xml、ERC JSON 到 erc.json，再运行 `python docs/mini-companion/validation/nfc-017/verify.py`。历史 before-format.xml 是格式化前连接证据，不随重跑覆盖。
