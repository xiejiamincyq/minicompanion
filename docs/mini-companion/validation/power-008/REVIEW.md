# HW-PWR-008 背光接入系统电源候选

2026-09-24；Astra 实施，背光选型经独立只读二审。状态：原理图评审通过，非制造放行。

## 实际变更

在 system_power_review 工程增加 backlight 子页，以层次引脚接入 VLOGIC_SWITCHED。U2 为 TPS60231RGTR；D1/D2/D3 并联接屏幕 LED_K，VOUT 接 LED_A。EN1/EN2 共接 BL_PWM，10k 下拉。VIN 与 MCU 计划使用同一切换后电源域，避免低电池时控制电平高于驱动 VIN。POWER 仍控制 TPS63802 EN，不切断充电、PACK 地和 NTC。

R6=8.06k、1%；输入/输出各1µF，飞跨电容各0.47µF，暂定10V X7R。电容实际料号、直流偏压后容量及 U2 标准 QFN 封装的完整机械复核待完成。J3/J4是评审连接边界，不新增产品插座。芯片散热焊盘17接地；2/3为芯片无连接脚。

## 数值及证据边界

名义总背光电流 58.06mA，低于屏幕80mA绝对最大值。按VISET 580–620mV、K 230–280及电阻1%计算为49.16–65.27mA；这是有条件的表格计算，不能宣称整个3.18V电源容差、全温及PFM状态下均保证该范围。K的表格条件含ISET=80µA，线性调整率条件为VIN≥3.2V；这些与当前实际工作点有差异，必须保留验证项。

电源预算不能把LED电流直接当输入电流。1.5倍电荷泵模式名义估算约89.2mA；目前为此支路预留110mA作为设计预算，非芯片保证上限，也不含整个MCU/NFC负载。两天续航尚未成立。

硬件PWM输入已留好；没有修改软件。后续测试覆盖低输入/温度下电流、PWM低亮度和长低电平重启、启动峰值、TPS63802 PFM纹波及屏幕3.3V上限、关机残光和反灌。没有进行实物测试。

## 验证与工具问题

KiCad 10.0.6 CLI：两页共22个器件，ERC 0错误/0警告。verify_backlight.py独立核对U2全部引脚、电容、LED极性、使能与公共电源，逐脚确认原HW-PWR-007电路不变；故意交换LED极性能够被检查捕获。system-review.pdf为当前两页预览。

MCP创建子页、符号和连接后，主页面内嵌TPS63802定义丢失，造成原有连线悬空。保留故障备份后，从9ad7b08恢复内嵌库，再使用结构化文本范围修复层次连接和字段排版，最后以官方CLI与独立网表检查验证。过程中一个层次引脚括号错误也已修复。没有降低ERC规则来隐藏问题；后续MCP改图必须检查自定义符号缓存仍存在。repair_cache.py/finish_drawing.py为一次性恢复过程记录，不是日常重建命令。
